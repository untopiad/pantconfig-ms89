# AGENTS.md — правила работы с кодовой базой PanteonConfig

Проект: Linux userspace конфигуратор мыши PANTEON MS89 (крейт `panteon-ms89`).
Протокол подтверждён живыми USB-трейсами; безопасность железа — высший приоритет. Ошибки в UI можно править итерациями, ошибки в wire-коде — невосполнимы.

## §0. Прежде чем писать хоть строку

1. `git status` — рабочее дерево должно быть чистым от чужих изменений; незавершённые правки спрятать (`git stash`) или довести до атомарного коммита.
2. Базовая линия тестов: `cargo test --quiet` (крейт) и `cargo check --features gui --bins` — оба должны проходить **до** начала и **после** каждого шага.
3. Свериться с `docs/adr/` (ADR-001 write-gate, ADR-002 no-readback, ADR-003 two-state-nibble) — регистровая карта не «на вскидывание»: любое новое значение `(bank, addr)` без подтверждения трейсами помечается «hypothesis, unconfirmed».

## §1. Нерушимые правила

1. **Тестовый шлюз:** тесты проходят до и после каждого шага; коммит атомарен, без смешивания слоёв.
2. **Write-Gate — не обходить.** Любая запись на железо идёт только через `device::gate` и `Transport::write_feature`. Добавление «прямых» `raw_write_feature`-вызовов в CLI/GUI/сервисах запрещено.
3. **Dry-run по умолчанию.** Изменение путей записи так, чтобы реальная запись происходила без явного подтверждения (`--confirm ...`), — регрессия уровня безопасности.
4. **Заморозка публичных контрактов:** форматы `ledger.toml` / снапшотов, сигнатуры handshake (`0x0976/0x0978`), layout PackedMem (`[0x07, 0x18, ...]`) — изменения требуют миграции формата и обновления ADR/доков, не молча.
5. **Модель без инфраструктуры:** `model/` не зависит от codec/device/gui; wire-преобразования только в `codec/`.
6. **UI-состояние ≠ домен:** поле `PanteonApp`, влияющее на dirty-tracking (`AppBaseline`), обязано синхронизироваться в `sync_baseline`; чисто визуальные поля (раскрытые панели, палитры) — НЕ добавлять в baseline.

## §2. Ловушки проекта

- **Модель ↔ codec рассинхронизация цвета:** `DpiLevel.color_rgb` — один цвет, а wire-код (`codec::dpi`) кодирует пару main/second каналов. Не «чинить» codec под модель — домену нужен `DpiSlot` с двумя цветами.
- **`written_at` — строка** в `ShadowEntry` и TOML-хранилище; любые сравнения по времени требуют парсинга. Замена на u64 — только вместе с миграцией формата.
- **Гипотезы кодируются как подтвержденные:** `polling_rate_codes::HZ_250` и часть LED-кодов — гипотезы; doc у `PollingRate::to_register_code` говорит «confirmed» — не расширять без live-трейса.
- **feature `gui`:** модуль `gui` собирается только под флагом; `cargo check` без фич GUI не проверяет. Проверять `cargo check --features gui --bins`.
- **GUI мутирует `PanteonApp` напрямую** из панелей; бизнес-логика записи — только в `service/` и `gui/actions.rs`. Не добавлять запись на железо из `panels.rs`/`*_panel.rs`.
- **Двойные алиасы регистров:** `ACTIVE_DPI_SLOT`/`CONFIG_STATUS`, `LED_EFFECT`/`LED_EFFECT_SPEED` — одно и то же значение; новые алиасы не вводить, старые не переименовывать без миграции.

## §3. Матрица размещения кода

| Что строите | Слой / папка | Обязательный тест |
|---|---|---|
| Доменные типы (Profile, DpiLevel, Snapshot) | `panteon-ms89/src/model/` | Юнит-тесты в `model/mod.rs` |
| Wire-кодирование/декодирование (кадры, nibble-цвет) | `src/codec/` | Тесты frames/round-trip в `codec/` |
| Транспорт, write-gate, транзакции | `src/device/` + `src/device.rs` | `tests/write_gate.rs`, `tests/escape_hatch.rs` |
| Use-cases (применение блока 0x18/0x38) | `src/service/` | `tests/cli_dispatch.rs`, dry-run сценарии |
| Персистентность TOML (ledger, snapshot) | `src/store/` | Round-trip тесты в `store/` |
| Разбор pcap/pcapng | `src/capture/` | Тесты на фикстурах `tests/fixtures/` |
| CLI-команды | `src/cli/` | Тест аргументов + dry-run вывод |
| GUI-панели и состояние окна | `src/gui/` | `cargo check --features gui`; тесты логики вне egui где возможно |

## §4. Философия дизайна

Разделение ответственности строже, чем DRY: **домен (`model`) описывает устройство, `codec` — wire, `device` — транспорт и безопасность, `service` — сценарии, `store` — память, `gui`/`cli` — только представление и ввод**. Знание о банках/адресах не просачивается выше `model`+`codec`; знание о HID-репортах не просачивается в `gui`. Если новая правка требует знания о wire-байтах в GUI — это нарушение границы, её место в codec или service.

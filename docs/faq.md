# Часто задаваемые вопросы (FAQ) — PANTEON MS89 Linux Configurator

Технический справочник по особенностям прошивки, протокола и аппаратного обеспечения игровой мыши PANTEON MS89 (USB VID `0x30fa`, PID `0x1440`).

---

### 1. Почему частота опроса (Polling Rate) не меняется мгновенно на лету?

**Кратко:** Частота опроса USB HID устройств задаётся дескриптором эндпоинта (`bInterval`), который ядро Linux считывает только в момент подключения устройства.

**Подробно:**
- Аппаратный интервал опроса определяется полем `bInterval` в `Endpoint 0x81 Interrupt IN`:
  - 1000 Hz $\to$ `bInterval = 1` (1 ms)
  - 500 Hz $\to$ `bInterval = 2` (2 ms)
  - 250 Hz $\to$ `bInterval = 4` (4 ms)
  - 125 Hz $\to$ `bInterval = 8` (8 ms)
- Запись значения частоты в регистр мыши (Bank 6, Addr `0x0018`) обновляет внутреннее состояние микроконтроллера и дескриптор в RAM/Flash. Однако USB-подсистема ядра Linux (`usbhid`) не перечитывает дескрипторы работающего устройства на лету.
- Чтобы новое значение вступило в силу, требуется **реэнумерация USB-устройства**:
  - Физическое переподключение (unplug / replug кабеля), ЛИБО
  - Программный сброс шины (**USB Soft-Reset**) через кнопку в GUI или команду `panteon-ms89 push-state`.

---

### 2. Что такое USB Soft-Reset и как его настроить без root-прав?

**Кратко:** Это программный аналог выдёргивания и повторного подключения USB-кабеля через системный вызов `ioctl(USBDEVFS_RESET)`.

**Подробно:**
- При вызове сброса ядро Linux посылает аппаратный сигнал RESET на соответствующий порт USB-концентратора. Контроллер мыши перезапускается, шина заново опрашивает дескрипторы устройства и сразу активирует обновлённый `bInterval`.
- Для выполнения сброса без прав суперпользователя (`sudo`) необходимо настроить правила udev:
  ```bash
  sudo cp udev/99-panteon-ms89.rules /etc/udev/rules.d/
  sudo udevadm control --reload-rules
  sudo udevadm trigger
  ```
- Правило `99-panteon-ms89.rules` присваивает тег `TAG+="uaccess"` как символьным узлам `/dev/hidraw*`, так и USB-устройствам `/dev/bus/usb/*/*`, обеспечивая доступ текущему активному пользователю рабочего стола через `systemd-logind`.

### 3. Почему нельзя выставить произвольный DPI (например, 8600 или 3500)?

**Кратко:** Оптический сенсор мыши (PixArt/Sunplus) и таблица прошивки поддерживают ровно 23 калиброванных дискретных шага.

**Подробно:**
- Точная таблица поддерживаемых значений подтверждена живыми USB-трейсами и наблюдаемым поведением официального конфигуратора:
  - **Базовый диапазон (шаг 200..800 DPI):** 200, 400, 600, 800, 1000, 1200, 1400, 1600, 1800, 2000, 2400, 3200, 4000, 4800.
  - **Высокий диапазон (шаг 800..1600 DPI):** 5600, 6400, 7200, 8000, 8800, 9600, 10400, 11200, 12800.
- В протоколе значение передаётся как 5-битный индекс (`0x01`..`0x18`). Младшие 4 бита пакуются в нибблы регистров Bank 5..7 @ `0x0010`, а старший бит (бит 4) объединяется в битовую маску множителя в Bank 3 @ `0x0010`.
- Промежуточные значения (например, 2200, 8600, 12000) не имеют аппаратного кода в таблице прошивки контроллера и не поддерживаются сенсором.

### 4. Что такое Shadow Ledger и почему мышь не отдаёт свои настройки?

**Кратко:** Микроконтроллер мыши физически не поддерживает чтение произвольных регистров. Конфигуратор использует локальный журнал доверия (`ledger.toml`).

**Подробно:**
- Аппаратное исследование и fuzzing-свип команд подтвердили архитектурное ограничение прошивки ([ADR-002](adr/ADR-002-no-register-readback.md)): команда чтения дескриптора (`0x18 mode 0x05`) возвращает исключительно фиксированную 32-байтную страницу дескриптора (Bank 0, Base `0x0000`). Произвольное чтение регистров EEPROM/Flash заблокировано прошивкой.
- Для обеспечения надёжности и предсказуемости конфигуратор ведёт локальный **Shadow Ledger** (`~/.local/state/panteon-ms89/ledger.toml`).
- При каждой подтверждённой записи (Level 2 Write) в журнал атомарно записывается кортеж `(bank, address, data, timestamp)`.
- В GUI реализован баннер **Expected Flash State ("Surface of Trust")**:
  - Если все необходимые регистры записаны через конфигуратор, отображается: `🔒 Flash State: содержит N подтверждённых записей`.
  - Если устройство только что подключено или записи не зафиксированы: `⚠️ UNKNOWN (Shadow ledger пуст)`.

### 5. Почему запись в постоянную память (SPI Flash) ограничена по умолчанию?

**Кратко:** Защита ресурса износа циклов перезаписи SPI Flash памяти микроконтроллера.

**Подробно:**
- Память Flash в микроконтроллере имеет конечный ресурс циклов перезаписи секторов (обычно 10 000 — 100 000 циклов).
- Финализация записи во Flash осуществляется специальным управляющим кадром `07 18 10 00 00 00 00 00` (`mode 0x10`).
- Обычные команды CLI (`set-polling`, `set-active-dpi-slot`, `set-fire-delay`) по умолчанию отправляют 5-кадровый хвост Soft-Apply **без сброса во Flash** (`mode 0x00` idle). Изменения активны в оперативной памяти контроллера до перезагрузки.
- Флаг `--commit-flash` в CLI или кнопка «⚡ Apply All DPI & Colors» в GUI явно передают кадр `mode 0x10`, записывая настройки в постоянную память только по осознанному требованию пользователя.

### 6. Как работают профили, пресеты и режим Full-Push (867 кадров)?

**Кратко:** Режим Full-Push синтезирует и воспроизводит сессию полной перезаписи всех банков регистров, на 100% повторяя официальное Windows ПО.

**Подробно:**
- При нажатии кнопки "Apply" в оригинальном приложении для Windows на шину USB всегда отправляется полная сессия из 867 кадров (пошаговая запись банков 0..7, матриц цветов, макросных слотов и финальный Flash flush).
- В Linux-конфигураторе режим **Full-Push** (`panteon-ms89 push-state --full` или кнопка в GUI):
  1. Загружает эталонный снапшот чистой конфигурации (`docs/state_reset.toml`).
  2. Накладывает на него все пользовательские параметры из локального Shadow Ledger.
  3. Воспроизводит последовательность кадров с верификацией Interrupt IN ACK на каждом шаге.
  4. Автоматически выполняет USB Soft-Reset.
- Встроенные пресеты (*Factory Default*, *High-DPI Competitive*) позволяют в один клик сбросить мышь к заводским настройкам или настроить турнирный профиль (1000 Hz, 8ms Fire delay, спортивные ступени DPI).

### 7. Почему в конфигураторе нет настроек чувствительности (Sensitivity) и скорости прокрутки (Scroll Speed)?

**Кратко:** Это системные настройки операционной системы Windows, мышь не имеет соответствующих аппаратных регистров.

**Подробно:**
- Анализ дампов USB (`sens_to-*.pcap` и `scroll_sp_to-*.pcap`) показал **ровно 0 изменённых байт** на шине USB во всех 867 кадрах при изменении этих ползунков в Windows GUI.
- Windows регулирует эти параметры чисто программно внутри драйверов `mouclass.sys` / `mouhid.sys`.
- В Linux чувствительность сенсора и скорость прокрутки настраиваются средствами рабочего окружения (GNOME / KDE Settings) или через правила конфигурации `libinput`.
